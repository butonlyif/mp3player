# Soul Play 界面舒适度与批量选择设计

日期：2026-08-09

## 目标

在不改变音乐库、播放列表和播放行为的前提下，改善日常界面的空间利用、字体层级与视觉舒适度，并让沉浸模式真正脱离浏览界面。同时统一音乐库和播放列表的桌面式批量选择体验，保留“移除”和“删除本地文件”能力。

## 设计方向

采用已确认的组合方案：

- 日常浏览使用“紧凑平衡”布局：工具按钮图标化、组件圆角化、字体和间距形成更清晰的层级。
- 沉浸播放使用“真沉浸”布局：隐藏侧栏和浏览工具栏，让歌词、氛围视觉与播放控制占据完整内容区域。
- 破坏性操作不进入常驻的四个浏览按钮，而在选择歌曲后出现，并同时保留在右键菜单中。

## 日常模式

### 顶部工具区

浏览页面右上角的常驻操作改为固定尺寸图标按钮，避免歌词抽屉打开后文字换行：

- 批量编辑：编辑图标。
- 均衡器：均衡器图标。
- 歌词：歌词图标。
- 沉浸模式：全屏或展开图标。

按钮使用 `aria-label` 和 `title` 提供可访问名称与悬停说明。按钮保持不换行、不可压缩，工具区在窄宽度下仍保持单行。当前开启的歌词、均衡器等状态使用强调色和柔和底色表示。

### 字体

继续使用系统字体栈，优先保证 macOS 与 Windows 的原生观感，不引入网络字体：

- macOS：SF Pro Text / PingFang SC。
- Windows：Segoe UI / Microsoft YaHei UI。
- 其他平台：system-ui / sans-serif。

正文保持适合高密度曲目列表的字号；标题、按钮、次要信息分别使用明确的字号、字重与颜色层级。中文界面避免过大的字间距，曲名与歌词比控制标签更醒目。

### 圆角与空间

- 应用内容面板、歌词抽屉和播放控制区使用一致的圆角 token。
- 主要内容容器采用约 12–14px 圆角，按钮采用约 8–10px 圆角，小型状态控件采用更小圆角。
- Tauri 窗口自身的外轮廓仍服从系统窗口能力；CSS 圆角用于内部内容表面，不假设能够改变操作系统窗口裁切。
- 歌词抽屉保留侧边布局，但设定响应式宽度和合理上限，不再固定占用过大的 580px。

## 沉浸模式

沉浸模式成为覆盖日常应用外壳的独立展示层：

- 隐藏标题栏之外的日常侧栏、浏览内容、浏览工具栏、歌词侧抽屉和普通播放栏。
- 沉浸层占满应用可用区域，歌词居中显示，背景视觉根据封面与音频响应生成。
- 底部保留精简播放控制、当前曲目信息和进度。
- 提供清晰的“退出沉浸”图标按钮；Escape 同样退出。
- 沉浸层不得影响后台播放状态、当前队列或歌词同步状态，切换只改变展示层。

## 批量选择

音乐库与播放列表采用一致的选择模型：

- 单击歌曲：仅选择当前歌曲，并把它设为新的范围选择锚点。
- Shift + 单击：选择锚点到当前歌曲之间、按当前可见排序排列的连续范围。
- Command + 单击（macOS）或 Ctrl + 单击（Windows/Linux）：切换当前歌曲的选中状态，不清除其他选择。
- 从歌曲列表空白区域按下并拖动：显示半透明矩形选框，选择与矩形相交的可见歌曲行。
- 点击列表空白处或按 Escape：清空选择。
- 搜索、排序或切换视图后，范围选择只基于新的可见顺序；不在当前可见集合内的选择应清理，避免对隐藏歌曲执行误操作。

框选只从列表背景或行内非交互区域启动。评分控件、按钮、菜单和滚动条不会启动框选。

### 与播放列表排序的冲突处理

播放列表的排序拖动改为从每行专用拖动把手开始。直接拖动行的其他区域用于框选或普通选择，不触发排序。拖动把手带有可访问名称，拖动期间不更新批量选择。

## 选择操作栏与危险操作

选择一首或多首歌曲后，列表顶部显示紧凑操作栏，并显示已选数量：

- 编辑标签。
- 加入播放列表。
- 从当前列表移除。
- 从音乐库移除。
- 删除本地文件。
- 取消选择。

操作根据上下文显示：音乐库视图不显示“从当前播放列表移除”；播放列表视图显示该操作。右键菜单保留对应的单曲和批量操作。

“移除”与“删除”必须语义明确：

- 从播放列表移除：仅解除歌曲与当前播放列表的关系，不改变音乐库和本地文件。
- 从音乐库移除：从音乐库索引中移除，不删除本地文件。
- 删除本地文件：从音乐库索引中移除并删除磁盘文件，使用红色危险样式，并在执行前显示包含歌曲数量和不可恢复说明的二次确认。

右键未选中的歌曲时，操作对象仅为该歌曲；右键已选中的歌曲时，操作对象为当前全部选择，菜单中显示数量，避免操作范围不明确。

## 组件边界

- `App`：根据沉浸状态选择日常应用外壳或沉浸展示层。
- `LibraryView` 与 `PlaylistView`：提供可见歌曲顺序、行元素和上下文操作。
- 共享选择交互单元：负责选择锚点、修饰键逻辑、Escape、框选几何计算和选择范围清理；两个列表复用同一套行为。
- 共享图标按钮：统一尺寸、活动状态、提示和可访问名称。
- Zustand store：继续作为已选歌曲集合的唯一数据源，并扩展为支持显式批量设置选择，避免框选时逐行触发状态更新。

## 错误与边界情况

- 空列表不启动框选，空白点击仍可清空选择。
- 框选过程中窗口滚动时，以当前可见行位置实时计算；第一版不实现靠近边缘自动滚动，以控制范围。
- 删除或移除失败时保留选择，显示错误信息，便于重试；成功后刷新对应列表并清空已完成操作的选择。
- 没有当前曲目时仍可进入沉浸模式，但显示空状态和退出入口，不渲染伪造的曲目信息。
- 窄窗口下，选择操作栏允许将低频危险操作收进“更多”菜单，但常驻四个浏览图标保持单行。

## 验证

### 自动化测试

- 选择模型：单选、Command/Ctrl 切换、Shift 范围、Escape 清空、视图变化后的清理。
- 框选：矩形相交计算、忽略交互控件、一次状态提交。
- 播放列表：拖动把手排序不会改变选择，行区域不会意外排序。
- 危险操作：三种移除/删除语义传递正确的 API 参数和歌曲集合。
- 沉浸模式：侧栏与日常工具栏不渲染，退出操作恢复日常布局。

### 手动检查

- 在歌词抽屉开启及窄窗口宽度下，四个图标按钮不换行、不竖排。
- macOS 与 Windows 字体回退、工具提示和 Command/Ctrl 行为正确。
- 日常模式的内容面板、歌词面板和播放栏圆角协调，没有裁切或双重边框。
- 沉浸模式中看不到左侧栏和浏览操作，歌词与播放控制保持清晰。
- 删除本地文件的确认文本与红色危险样式足够醒目。

## 非目标

- 不更换整体暖色主题。
- 不引入第三方图标库或网络字体；图标优先使用项目内联 SVG 组件。
- 不修改音频引擎、歌词解析、数据库结构或播放队列规则。
- 第一版框选不包含边缘自动滚动、触控手势或键盘方向键扩展选择。
